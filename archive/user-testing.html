User Testing & Feedback Analysis

After developing the Figma prototype in collaboration with Nana, we conducted a small-scale user testing session through a structured questionnaire to evaluate the clarity, usability, and overall perception of the TeleAgriculture system.

Overall, the feedback revealed a mixed but insightful response, highlighting both strong engagement with the visual and navigational logic, as well as expectations that extended beyond the intended scope of the prototype.

Positive Feedback

Users responded positively to several core aspects of the system:

  • Navigation clarity was generally strong, with 100% of users agreeing or strongly agreeing that features were easy to find.
  • The data visualisation and dashboard elements were well received, with users noting that the system was visually appealing and effective in communicating environmental data.
  • 100% of participants confirmed that they understood what the data represented, suggesting that the visual language successfully reduced cognitive barriers.
  • The globe-based interaction and project linking system were also highlighted as engaging and conceptually interesting.

These results indicate that the core design intention creating an intuitive, visually driven environmental data interface was largely successful.

Key Issues Identified

However, the feedback also exposed several important usability and expectation gaps:

  • Some users felt the system contained too many sections and excessive content density, especially within the Shop and Project areas.
  • There was confusion around the scope of the prototype, as some participants expected a fully functional application rather than a design-led Figma concept.
  • Several users suggested that the interface would benefit from more standardisation and a clearer content hierarchy, particularly in how information is presented across pages.
  • The data dashboard and detail pages were seen as slightly fragmented, with some users preferring a more unified or customisable interface.
  • A few participants expressed that the globe-based interaction might be more suitable for a web-based platform rather than a mobile app, highlighting platform expectation issues.

Feature Expectations

Users also identified missing or expected features, including:

  • Customisation options for dashboards and data views
  • A wiki or knowledge base for agricultural guidance
  • Troubleshooting and system explanation pages
  • More detailed graphs and parameter controls
  • Visibility of system status (e.g., sensor connectivity, data streaming state)

This feedback suggests a strong demand for the platform to evolve into not only a data visualisation tool, but also a knowledge-sharing and configuration system.

Critical Reflection on Testing Context

It is important to note that some feedback was influenced by a misunderstanding of the prototype scope. While the project primarily focused on UI/UX design, interaction logic, and system structure, some participants interpreted it as a fully developed application with complete functionality.

Additionally, because the evaluation was conducted on a Figma prototype rather than a fully interactive coded system, certain expectations around performance, real-time functionality, and completeness naturally emerged.

This mismatch highlights the importance of clearer framing during future testing phases, particularly when evaluating conceptual or design-led prototypes.

Summary

Overall, the user testing results confirm that the TeleAgriculture interface successfully communicates its core data-driven concept and supports intuitive navigation. At the same time, the feedback provides clear directions for future iteration, particularly around:

  • Reducing interface complexity and content overload
  • Introducing stronger information hierarchy and standardisation
  • Expanding customisation and knowledge-based features
  • Clarifying system scope and interaction expectations

These insights will directly inform the next development stage of the project.
