Multi-Sensor Integration & System Logic

In Week 3, I moved beyond single-purpose devices to build a Multi-Sensor Integrated System. Using an ESP32, I combined a DHT22 (Temperature/Humidity), an HC-SR04 (Ultrasonic Distance Sensor), an OLED Display, and LEDs. The goal was to create a cohesive system where different hardware components influence one another’s behaviour in real-time.

Technical Challenges & Solutions

The primary challenge this week was managing timing and concurrency. Unlike simple LED blinking, sensors like the HC-SR04 and DHT22 require specific timing intervals.

  • The Problem: Using delay() to slow down the OLED display would interfere with the Ultrasonic sensor’s ability to trigger and receive pulses accurately.
  • The Solution: I shifted from using delay() to non-blocking timing logic using millis(). This allows the ESP32 to “multi-task” reading sensors at high speed while updating the OLED screen at a readable 200ms interval.

Another challenge was Data Presentation. Formatting data for a small OLED screen (128×64) required careful coordinate management. I learned to use the Adafruit_SSD1306 library to create a clean UI that displays multiple sensor readings simultaneously without overlapping.

Hardware Mapping & Integration

This week also deepened my understanding of communication protocols:

  • I2C Protocol: Used for the OLED display (SDA/SCL), allowing me to save GPIO pins.
  • Digital Trigger/Echo: Used for the Ultrasonic sensor, requiring precise microsecond pulses.
